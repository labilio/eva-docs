# Eva 协作文档重写计划

> 执行方式：后续使用 executing-plans 按任务推进；当前仅制定计划，不改用户文档，不提交或部署。

**Goal:** 让初次使用 Eva 的读者理解协作对象之间的关系，能够选择正确入口、完成操作并预判影响。

**Architecture:** 保留 VitePress，重组 Markdown 的叙述与章节职责。以 Eva 现行产品决定为准，Octo-Web 仅用于核对已接入的交互语义。内部计划位于已排除发布的 maintainer 目录。

**Tech Stack:** VitePress 1.6.4、Markdown、现有截图。

**Spec:** 本轮用户要求；Eva 仓库 docs/项目与群聊成员体系.md、docs/群聊退出与解散规则.md、docs/消息关注与项目置顶.md、docs/会话内项目任务规范.md；本机 references/octo-web c2e2aee。

## 约束

- 产品名 Eva 智能办公系统；个人入口使用 我的 Agent。
- 章节使用自然功能名，不批量冠以“什么是”。
- 产品规范、代码表现、目标能力分别核对，不把演示能力写成已接入服务。
- Octo-Web 的全部能力不自动成为 Eva 的能力。
- 不改变产品行为，不因文档研究增加功能。

## 审阅重点

1. 非项目群不能被遗漏；项目不是所有聊天的必经入口。
2. 身份类型、成员资格和管理角色分开解释。
3. 子区分开讨论内容，但不建立独立成员权限。
4. 个人整理操作与影响所有人的管理操作明确区分。
5. 规范历史冲突不得直接变成面向用户的确定承诺。
