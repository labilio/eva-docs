# 产品内帮助与文档联动

订阅成功通过按钮状态反馈，失败才显示错误 Toast。产品通过操作结果解释基本用途，帮助文章解释规则和例外。任务列表不常驻教学说明，不自动弹出订阅介绍。用户帮助不直接复制内部机制规格，也不承诺原型尚未实现的能力。

## 现有对应关系

| 产品主题 | 产品内入口 | 稳定文档路径 |
| --- | --- | --- |
| 任务 | 项目顶栏「使用帮助」 | `/team/projects#项目任务`，其中链接到任务订阅详情 |
| 群聊 | 同上 | `/team/messages` |
| 文件 | 同上 | `/resources/files` |
| 自动化 | 同上 | `/team/projects#project-automation` |
| 项目信息 | 同上 | `/team/projects#project-info` |
| 项目设置 | 同上 | `/team/projects#项目成员` |

Eva 原型通过 `prototype/004-product-help.js` 的 `EvaHelp` 映射管理地址。文档站和产品原型独立部署；链接在新标签页打开，保留产品中的任务上下文。

## 修改与验收

1. 以已确认的业务机制为依据，同步更新用户说明和原型；待定规则不写成已提供能力。
2. 文章先说明用途与操作，再解释自动行为、退出方式与例外。涉及原型与真实能力差异时标明当前演示范围。
3. 预览中从真实产品入口打开文章，检查路径、内容、返回原产品后的状态，以及文档目录和搜索是否可找到文章。
4. 用户验收后才能发布。新增入口上线前先发布目标文章并检查可访问性，再发布产品入口。
5. 修改标题不必更改路径。必须移动文章时，同时维护旧地址跳转和产品映射，避免失效链接。

正式研发可替换文档服务与域名，但应保留主题标识、入口位置、文章内容与跳转行为的约定。
