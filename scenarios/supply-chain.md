# 从供应链讨论到任务跟进

这篇实践用一项批次整改工作，带你走完“整理问题—项目讨论—创建任务—跟进进度”。完成后，你应该能找到这项工作的讨论位置和任务编号，知道接下来由谁处理。

## 准备示例材料

使用已有的「供应链运营协同」项目，确认你能访问该项目及相关群。无需另建项目或人员。

以下为练习材料，不是真实业务指令：

```text
供应链晨会记录：
采购部周五前确认替代供应商报价。
质量部需要复核 A-2409 批次问题，并收集整改证据。
质量部的具体负责人和截止日期尚未确认。
```

本次重点跟进第二项。涉及真实责任人和日期时，要先取得实际确认。

## 1. 整理出需要讨论的问题

在个人 Eva 新建对话，粘贴材料，并提出要求：

```text
请根据这段会议记录，列出 A-2409 批次整改的待确认问题。
按“问题、需要的材料、需要确认的责任分工”组织。
没有依据的信息不要补写。
```

下面是供学习的人工整理示例：

| 问题 | 需要的材料 | 待确认分工 |
| --- | --- | --- |
| 需要复核哪些问题 | 批次问题清单 | 谁负责整理清单 |
| 整改证据是否齐全 | 对应整改材料 | 谁负责补充与核对 |
| 何时完成复核 | 团队确认的时间安排 | 由谁确认截止日期 |

当前原型可能只返回模拟确认。可以直接用这份示例继续练习，不必等待原型生成真实分析。

## 2. 到项目群确认

打开「我的消息」，进入“供应链运营协同”下有权访问的群。核对右侧项目名称，再发送需要确认的事项：

```text
请协助确认 A-2409 批次整改安排：
1. 问题清单与整改证据分别由谁整理？
2. 当前还缺哪些材料？
3. 复核预计何时完成？
未确认的事项先标为待确认，确认后再更新任务。
```

已有对应专题子区时，在该子区继续讨论。个人对话不会自动分享至项目群，发送前先检查材料是否适合当前群成员阅读。

## 3. 将事项创建为项目任务

在项目群或子区右上角点击「创建任务」，检查顶部所属项目，然后填写：

| 字段 | 示例 |
| --- | --- |
| 标题 | 确认 A-2409 批次整改证据 |
| 描述 | 核对问题清单与证据，列出缺项；完成标准为材料可查看、结论经负责人确认 |
| 状态 | 待办 |
| 执行负责人 | 选择当前项目中已确认负责的联系人，未确认时留空 |
| 截止日期 | 填写已确认日期，未确认时留空 |

![创建任务时核对项目、标题、描述及属性](/images/task-create.png)

点击创建后记下完整编号。会话保持在原位置，任务不会自动作为卡片发到群里。

## 4. 回到项目核对记录

打开「我的项目」中的“供应链运营协同”，进入任务页找到刚创建的任务。

检查描述、负责人和日期是否与讨论一致。需要分别跟进时，在子任务区创建「整理问题清单」「收集整改材料」，各自填写负责人和进度。

要告知同事，可以把实际生成的完整任务编号和标题发回原讨论，再说明需要谁确认。不要使用手册中的虚构编号代替刚创建的真实编号。

## 5. 更新进展并检查完成标准

开始处理后改为进行中。缺材料导致工作停住时，可改为受阻，并补充具体缺项与需要谁协助。

材料齐全、结论待核对时，按团队约定更新审核状态。确认完成前，打开附件检查证据，查看子任务是否还有未完成事项，再更新最终状态。

状态改变只是记录工作进展，不会让 AI 自动执行整改，也不能替代负责人确认。

## 怎样判断这次练习完成了

你应该能够重新找到原讨论及对应任务，说明它属于哪个项目、谁负责、还有哪些待确认事项。任务中有可核对的完成标准，状态与实际进度一致。

需要补充细节时，阅读[项目任务](../team/tasks.md)、[子区](../team/subareas.md)或[文件库](../resources/files.md)。
