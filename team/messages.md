# 群聊与子区

群聊把需要一起沟通的人组织起来；子区把同一个群里的不同话题分开。先确定谁需要参与，再决定是否需要拆分话题，会更容易选对沟通方式。

例如，在「供应链运营协同」项目中，全员群可以同步保供进展。需要集中讨论某次供应商整改时，可以在合适的群下建立子区，把整改问题、证据和后续回复放在一起。若这件事只适合部分项目成员参与，应先组织一个成员范围合适的普通群。

## 群聊的类型

群聊可以属于项目，也可以独立存在。项目群便于围绕持续工作开展沟通；非项目群适合不依附某个项目的交流，例如临时协调一次跨部门会议。

| 对比 | 项目全员群 | 项目普通群 | 非项目群 |
| --- | --- | --- | --- |
| 所属项目 | 有 | 有 | 无 |
| 创建方式 | 创建项目时自动建立，每个项目唯一 | 项目联系人按需要创建 | 按沟通需要创建，无需先建项目 |
| 联系人成员 | 与项目同步 | 从当前项目联系人中添加 | 从公司内已激活的联系人中添加 |
| 常见用途 | 整体通知、共同进展 | 部分成员的专项沟通 | 临时协调、跨部门交流 |
| 能否使用子区 | 可以 | 可以 | 可以 |
| 会话内项目任务入口 | 有权限时提供 | 有权限时提供 | 不提供 |
| 退出与解散 | 在项目层处理，不能单独退出或解散 | 可以退出，仅群主可以解散 | 可以退出，仅群主可以解散 |

加入项目会进入全员群，但不会进入所有普通群。项目负责人和管理员也需要先加入某个普通群，才能查看这个群里的消息。

## 群聊与子区的关系

子区是所属群聊中的专题讨论空间。“所属群聊”也称父群，父群与各子区可以分别发送和查看消息。

| 对比维度 | 群聊与子区的关系 | 使用时意味着什么 |
| --- | --- | --- |
| 讨论上下文（聊天记录） | **分别保存**：父群与各子区有各自的消息记录 | 在整改子区发送的消息属于整改子区；回到父群会看到父群的讨论 |
| 输入草稿 | **分别保存**：父群与每个子区各自保留草稿 | 切换话题不会把另一处尚未发送的内容变成本子区的草稿 |
| 参与人员 | **共享成员范围**：子区沿用父群成员 | 不必再邀请一次，也不能在子区中另选一部分群成员 |
| 访问权限 | **继承父群**：能访问父群的成员可以访问其子区 | 子区不是群内的私密讨论室；离开父群后会失去全部子区访问权 |
| 成员与管理权限 | **沿用父群的管理关系** | 不为子区另设群主、管理员或拉人、踢人流程；具体管理操作仍按角色显示 |
| 项目归属 | **跟随父群** | 项目群的子区属于同一项目；非项目群的子区也不属于项目 |
| 群头像 | **沿用父群** | 更换群头像后，需要显示头像的子区入口同步变化 |
| 群级 Bot 回复许可 | **沿用父群** | 群聊关闭免 @ 许可时，其子区也需要明确 @ Bot |
| 置顶与隐藏 | **按个人、按子区设置** | 整理自己的列表，不改变其他人的成员资格与访问范围 |
| 清空聊天记录 | **只作用于当前账号的当前会话** | 清空父群不清空子区；清空一个子区不影响其他子区 |

::: info 关于 AI 上下文
这里的“上下文分别保存”指各处的聊天记录和讨论线索分开。真实 AI 会读取哪些历史、文件和项目资料，还取决于实际接入的服务与授权；当前体验版不能用来验证模型上下文完全隔离。
:::

子区没有独立的加入或退出关系。即使没有在某个子区发过消息，父群成员仍可以访问它。需要缩小参与范围时，应建立合适的群聊，而不是通过子区隐藏内容。

## 群里的成员

查看成员时，先区分“这个身份是谁”，再看“它在当前群中有什么权限”。姓名旁的 AI 标识用于区分 AI 与联系人，并不表示管理员身份。

| 身份 | 怎样参与 | 需要注意 |
| --- | --- | --- |
| 联系人 | 由现有成员直接添加，或随项目同步进入全员群 | 只能添加当前范围内合资格的联系人，无需审批或接受邀请 |
| 云端分身 | 由主人带入；项目普通群要求分身已在项目中，且主人已在群内 | 不能替别人添加分身；主人离群，分身同步离群 |
| 项目管家等已接入的 AI | 按对应项目或 AI 接入方式参与 | 以当前群实际成员为准，不能因为 AI 属于某项目就认为它能访问所有群 |
| 数字员工与个人助理 | 使用各自的专门入口 | 数字员工加入项目不等于可以从普通群成员选择器拉入；个人助理不通过普通群拉人流程加入 |

「我的 Agent」中的 AI 小队有自己的成员组织方式，见[AI 小队](../personal/squads.md)。不要把小队的 AI 选择范围套到普通项目群上。

### 添加成员

1. 打开目标群，点击右上角三点进入聊天信息。
2. 在成员区域打开添加入口，选择联系人，核对名单后确认。
3. 回到成员列表查看添加结果。对方加入后，也会获得该群全部子区的访问权。

| 当前所在位置 | 应在哪里添加 | 可以选择的联系人 |
| --- | --- | --- |
| 项目全员群 | 进入项目添加成员流程 | 公司内已激活、尚未加入项目的联系人 |
| 项目普通群 | 当前群的添加成员入口 | 已加入当前项目、尚未加入本群的联系人 |
| 非项目群 | 当前群的添加成员入口 | 公司内已激活、尚未加入本群的联系人 |
| 子区 | 回到所属群聊处理 | 沿用父群范围，不单独添加 |

### 群主与管理员

| 角色 | 可以做什么 | 不因此获得什么 |
| --- | --- | --- |
| 普通联系人成员 | 添加合资格联系人、带入自己的分身、退出普通群 | 不能移除其他联系人或其他人的分身 |
| 群管理员 | 在权限范围内管理成员、群资料及群级设置 | 不因管理员身份获得转让群主或解散群聊的权限 |
| 群主 | 管理本群、设置联系人管理员、转让群主、解散普通群 | 不因此获得其他群或其他项目的权限 |
| 云端分身 | 在已加入的范围内参与协作 | 不继承主人的群主或联系人管理员权限 |

项目负责人或管理员已经在群内时，会获得相应群管理权限。群主也可以手动设置联系人管理员；手动授权与项目角色带来的权限分别生效。全员群的成员仍由项目同步，不能套用普通群的单独移除、退出和解散操作。

## 打开会话与发送消息

「我的消息」提供关注和最近两种查找方式，打开的是同一份会话。

| 入口 | 适用情况 | 对成员和权限的影响 |
| --- | --- | --- |
| 关注 | 持续查看固定项目，按群聊及子区找到讨论 | 只整理个人访问入口，不改变成员关系 |
| 最近 | 找回刚刚参与的会话，跨项目继续沟通 | 不改变归属；子区显示为单独一行也仍属于原群 |

1. 进入「我的消息」，从关注或最近中打开目标群。
2. 查看右侧标题及项目归属，确认消息要发给谁。
3. 输入并发送内容，检查消息出现在当前会话中。

需要进入某个话题时，在群下选择子区，或打开父群的子区面板。子区标题会显示所属群与当前子区名称，发送前先核对位置。

### 创建子区

1. 打开需要拆分话题的群聊，进入子区面板。
2. 使用创建入口，填写能说明讨论主题的名称，例如“供应商整改”。
3. 创建后打开该子区，发送相关背景与需要讨论的事项。

子区不再向下创建另一层子区。主题发生变化时，可以回到父群，为新的话题建立另一个子区。

以下是一条适合放在整改子区中的消息：

```text
请确认 A-2409 批次整改证据是否齐全。
如果还有缺项，请列出材料名称、负责补充的人和预计时间。
尚未确定的内容请标为待确认。
```

个人对话里的材料不会因为你进入群聊就自动分享。请先确认材料适合当前成员阅读，再补充到本次讨论中。

### 请 AI 参与讨论

在输入框输入 `@`，从当前成员候选中选中目标 AI，再写清请求。与单个 AI 私聊时，可以直接发送。群聊设置中的“Bot”指参与会话的 AI，免 @ 回答表示不必每次明确提及它。

| 场景 | 使用方式 |
| --- | --- |
| 希望群里的某个 AI 回应 | 明确 @ 该 AI，避免只在文字中输入名字 |
| 群聊允许 Bot 免 @ 回答 | 还需要该 Bot 已由主人开启免 @；任一侧关闭时仍须明确 @ |
| 子区中请 AI 回应 | 沿用所属群的群级许可，不单独绕过父群设置 |
| 使用 @所有人 | 通知联系人，不批量要求所有分身回应 |

群级许可位于聊天信息的「群聊管理」，由有管理权限的联系人操作。项目管家可按项目规则同步事项与提醒，但这不表示普通 AI 都会主动插话。当前原型回复可能只是确认回执，实际执行范围见[适用范围](../help/scope.md)。

## 整理与管理子区

置顶、隐藏和归档解决不同问题。只是暂时不想在自己的日常列表里看到某个子区时，可以使用隐藏。

| 操作 | 作用范围 | 与成员和消息的关系 |
| --- | --- | --- |
| 置顶子区 | 调整自己的父群内子区排序 | 不改变成员范围，也不改变最近列表按时间排列的方式 |
| 隐藏子区 | 从自己的日常列表收起 | 仍有访问权，不删除消息，不影响其他成员 |
| 恢复隐藏 | 从父群子区面板的「已隐藏」中恢复 | 重新显示原子区，不是重新加入 |
| 免打扰 | 调整当前账号的提醒 | 不退出；父群免打扰时，子区也保持静音 |
| 归档或取消归档 | 管理讨论主题的状态 | 与个人隐藏不同，在已归档列表中查看；不建立新的成员范围 |
| 清空子区记录 | 当前账号在当前子区的可见历史 | 不清空父群、其他子区或其他成员的记录 |

隐藏后，普通新消息不会自动恢复显示。“被 @ 时自动取消隐藏”默认关闭；开启后，新增消息明确提及本人时才会恢复，@所有人或 @自己的 AI 不会触发这一设置。

## 退出与解散

退出改变自己的成员关系，解散影响整个群。操作前请查看确认提示中的群名与影响范围。

| 操作 | 影响谁 | 群聊与子区会怎样 |
| --- | --- | --- |
| 退出普通群 | 本人及本人的分身 | 失去本群全部子区访问权；其他成员继续使用群和子区 |
| 群主退出，仍有人可接任 | 原群主及其分身 | 系统自动转让给其他有效联系人，也可先手动转让；群和子区继续存在 |
| 群主退出，无人可接任 | 整个群 | 确认后退出并解散，本群及全部子区不再可访问 |
| 群主主动解散普通群 | 所有成员 | 本群及全部子区不再可访问 |
| 希望退出全员群 | 本人及分身的项目关系 | 需要在项目层退出，并同时影响项目普通群及相关子区 |
| 希望只退出一个子区 | 没有独立退出关系 | 可按需要隐藏或免打扰；退出父群会同时失去全部子区访问权 |

AI 不能作为群主接任者。单独清空聊天记录不会退出群聊，历史作者关系也不会因成员离开而被改写。

讨论明确后，可以在项目群或其子区中[创建项目任务](./projects.md#创建任务)。任务进入所属项目，便于继续跟进；非项目群没有这个项目任务入口。
