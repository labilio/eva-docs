# 项目

项目是团队围绕共同目标开展工作的地方。参与成员、讨论、任务和资料都在这里组织，方便大家了解正在做什么、由谁负责，以及接下来需要跟进什么。

以「供应链运营协同」为例：采购和质量同事加入项目，在群里同步保供情况，把某次供应商整改放到子区中讨论，再将需要补充的材料建成任务，明确负责人和截止日期。之后，成员可以沿着任务找到进展和相关资料，继续同一项工作。

## 项目中的协作

| 内容 | 解决的问题 | 与其他内容的关系 |
| --- | --- | --- |
| 项目成员 | 谁参与这项工作 | 加入项目后自动进入全员群；普通群另行添加成员 |
| 项目全员群 | 怎样向项目成员同步信息 | 每个项目只有一个，成员随项目同步 |
| 项目普通群 | 怎样让部分项目成员集中讨论 | 从当前项目成员中组织参与者，不自动包含所有项目成员 |
| 子区 | 同一群里的不同话题怎样分开讨论 | 隶属于群聊，消息分别保存，成员与访问权限沿用所属群 |
| 项目任务 | 谁负责、何时完成、进展怎样 | 属于项目，可以从项目页或项目群及其子区中创建 |
| 项目文件 | 相关资料在哪里查找 | 在所属项目的文件范围内整理和访问 |

一次协作通常可以这样推进：

1. **明确目标和参与者**：创建项目或进入已有项目，添加需要共同工作的同事。
2. **讨论具体事项**：在全员群同步整体情况，在普通群或子区中讨论具体问题。
3. **记录分工**：把已经明确的事项创建为项目任务，填写负责人和完成标准。
4. **跟进结果**：更新任务进展，补充材料，让其他成员能够接着处理。

临时沟通也可以直接建立不属于项目的群聊。例如，几位跨部门同事确认一次会议安排，不必为此先建项目。需要持续组织成员、分工和资料时，再使用项目。两种群聊的区别见[群聊与子区](./messages.md#群聊的类型)。

## 创建与打开项目

### 创建项目

开始前，先确认这项工作是否已经有项目，避免把同一项工作的讨论和任务分散到不同地方。

1. 进入「我的项目」，打开新建项目入口。
2. 填写项目名称与共同目标，让参与者知道要一起完成什么。
3. 选择参与成员。至少选择一位成员；创建者本人不计入这一选择数量，也可以选择自己的可用分身。
4. 提交后，核对项目名称和成员列表。

创建者成为项目负责人，系统同时建立唯一的全员群。所选联系人进入项目和全员群，但不会自动带入各自的分身。

### 打开并关注项目

1. 点击左侧「我的项目」，找到你参与的项目。首次体验可打开「供应链运营协同」。
2. 核对项目名称，再查看任务、成员或相关资料。
3. 经常使用时，在项目列表使用「关注」，以后可通过消息的关注视图找到相关讨论。

关注只改变个人列表中的组织方式，不授予额外访问权限。取消关注也不会退出项目；部分界面说明使用“置顶”表示这一整理用途。

## 项目成员

### 添加同事

项目负责人、管理员和普通成员都可以添加公司内已激活 Eva 的联系人。

1. 在当前项目打开成员管理，点击「添加成员」。
2. 搜索或选择需要加入的联系人，核对已选姓名。
3. 确认添加，再回到成员列表查看结果。

添加成功后直接生效，无需对方再接受邀请。对方自动进入全员群，但不会自动加入项目中的所有普通群。

| 成员关系 | 如何建立 | 加入后可以参与什么 |
| --- | --- | --- |
| 公司联系人 | 使用公司内已激活的 Eva 账号 | 可以成为项目或群聊的添加候选；出现在通讯录不等于已加入项目 |
| 项目成员 | 由现有项目成员直接添加，或创建项目时加入 | 参与项目，并自动进入项目全员群 |
| 项目普通群成员 | 从当前项目成员中另行添加 | 访问这个普通群及其全部子区 |
| 子区参与者 | 沿用所属群的成员关系 | 无需再次加入；在所属群中就有该群子区的访问权 |

::: tip 找不到要添加的人
先检查对方是否已经加入，再确认是否为公司内已激活的联系人。项目普通群只能从当前项目成员中添加；对方还不在项目时，需要先添加到项目。
:::

### AI 如何参与

人的成员资格和 AI 的参与方式分别管理。把同事加入项目，不会自动把他的分身也带进来。

| 身份 | 参与方式 | 需要注意 |
| --- | --- | --- |
| 云端分身 | 由主人自行带入项目，随后同步进入全员群 | 每人最多一个；主人必须仍在项目中，不能替别人带入分身 |
| 数字员工 | 从数字员工详情中的「加入项目」入口使用 | 加入项目不等于自动成为任意群的成员，不能用普通拉人流程代替其专门入口 |
| 项目管家 | 按所属项目提供事项同步和提醒 | AI 的项目协作身份不等于联系人管理员，也不扩大项目或群的访问范围 |
| 个人助理 | 在个人工作和「我的 Agent」中使用 | 不通过普通项目、群聊的添加成员流程加入 |

分身不继承主人的负责人或管理员权限。主人离开项目后，其分身同步离开；单独移除分身则不会移除主人。各类 AI 的使用方式见[我的 Agent](../personal/my-ai.md)。

### 管理权限与工作分工

“项目负责人”“管理员”决定谁能管理项目；“采购”“质量”等角色描述工作分工。设置业务角色不会自动授予管理权限。

| 项目身份 | 主要权限 | 范围限制 |
| --- | --- | --- |
| 项目负责人 | 管理项目和成员、设置管理员、转让负责人 | 必须且只有一位联系人；主动退出前先完成转让 |
| 项目管理员 | 管理项目成员及相应项目设置 | 未加入某个普通群时，不能仅凭项目身份查看该群消息 |
| 普通成员 | 添加合资格联系人、带入自己的分身、创建项目普通群和任务 | 不能因此移除其他成员或取得管理员权限 |
| 云端分身 | 在已加入的范围内参与协作 | 不能成为项目负责人、联系人管理员或群主 |

项目负责人或管理员加入项目普通群后，会在该群获得相应管理权限；这不会使其成为群主，也不授予解散群聊的权限。

需要标明成员负责采购、质量等业务时，负责人或管理员可在成员管理的「角色设置」中选择成员并设置。某一项任务具体由谁执行，则在任务中选择执行负责人。

## 项目任务

项目任务是一条可以持续跟进的工作记录，包含所属项目、完整编号、状态、负责人、截止日期、讨论和附件。

群里的一句“请核对整改证据”仍是一条消息。讨论明确后，需要创建任务，团队才能围绕同一编号持续跟进。发送消息或让 Eva 整理清单，都不会自动生成项目任务。

![供应链运营协同项目任务看板，按状态查看各项工作](/images/tasks.png)

### 创建入口

| 入口 | 适用情况 |
| --- | --- |
| 我的项目中的任务页 | 集中整理或安排项目工作 |
| 项目群或其子区右上角「创建任务」 | 讨论清楚后，立即记录事项 |

会话中的创建入口使用当前群所属项目。个人 Eva、私聊和非项目群不提供这个项目任务入口。

### 创建任务

以下用「供应链运营协同」中的示例工作练习。开始前，确认你能访问该项目和对应群。

#### 1. 打开创建表单

在项目任务页点击创建入口，或在项目群右上角点击「创建任务」。先检查表单顶部项目名称。

![项目任务创建表单：顶部所属项目、标题与描述，以及底部属性选择](/images/task-create.png)

#### 2. 写清工作与完成标准

标题填写「确认 A-2409 批次整改证据」。描述可以使用下面的示例：

```text
核对 A-2409 批次的问题清单与整改证据。
列出仍缺少的材料，并与负责同事确认补充安排。

完成标准：
证据材料可查看；仍未解决的问题已明确列出；结论经负责人确认。
```

标题必填。描述虽可不填，但写清完成标准，后续更容易判断工作是否完成。

#### 3. 设置状态和负责人

| 字段 | 第一次填写时怎样选择 |
| --- | --- |
| 状态 | 尚未开始时保留「待办」 |
| 优先级 | 根据团队实际安排选择，暂未确定可保留默认 |
| 执行负责人 | 从当前项目联系人中选择；未确定时可先不指派 |
| 截止日期 | 填写已经确认的日期，未确认时留空 |

手动创建的来源者与创建者是当前操作人，这两个字段不在创建弹窗改选。AI 身份不作为执行负责人候选。

#### 4. 提交并核对

点击「创建」，记下成功提示中的完整编号，包括项目前缀。到该项目任务页找到新任务，检查标题、状态、负责人及截止日期。

从聊天创建后会留在当前会话，任务进入所属项目；不会自动向聊天发送任务卡片。需要通知同事时，另发任务编号和需要跟进的事项。

### 选择视图

| 视图 | 适合查看什么 |
| --- | --- |
| 看板 | 各状态下有哪些任务 |
| 列表 | 连续浏览任务并逐项处理 |
| 层级 | 父任务与子任务的分解关系 |
| 表格 | 集中浏览任务字段 |

子任务在看板中也作为独立卡片显示。要看它属于哪个父任务，使用层级视图或任务详情的子任务区。

### 更新进展

打开任务，在详情中根据实际进度调整状态，必要时补充说明。下面是理解各状态的常见方式，具体流转按团队约定：

| 状态 | 适用情况 |
| --- | --- |
| 待办 | 已记录，尚未开始 |
| 进行中 | 正在处理 |
| 审核中 | 已提交结果，等待核对 |
| 已完成 | 工作及完成标准已核对 |
| 受阻 | 存在需要解决的依赖或问题 |
| 已取消 | 不再继续这项工作 |

修改状态只记录进度，不会启动 AI 执行。标为受阻时，写明缺什么、需要谁协助，比单独改变标签更便于接手。

### 子任务

打开父任务，在子任务区点击「开始分解」或已有的创建入口。检查创建路径包含父任务编号，再填写子任务。

例如，可以把证据核对拆成「整理问题清单」与「收集整改材料」。它们属于同一项目，但各自设置状态、负责人和截止日期。

完成父任务不会自动完成子任务。有未完成子任务时，先核对提示；删除父任务前，要先处理它的子任务。层级较深时可使用「展开全部层级」查看。

### 任务附件

创建时可以选择多个附件，当前原型单文件上限为 20 MB。打开任务详情中的文件可预览；需要本地副本时下载，需要集中整理时使用保存到项目文件库的入口，并到目标位置核对。

::: info 体验版保存范围
当前任务及附件用于页面内演示，不能作为后端备份或跨设备同步的依据。请使用示例材料，正式交付前还需验证真实保存服务，见[适用范围](../help/scope.md)。
:::

## 项目文件

任务附件适合随具体事项查看，项目文件库适合集中整理项目资料。在任务详情中把文件保存到项目文件库后，到目标位置核对；不要仅凭聊天中提到了文件名，就认为资料已经保存。

个人对话分组、个人文件与项目没有自动共享关系。即使名称相同，也不会因此向项目成员开放。资料管理的具体操作见[文件库](../resources/files.md)。

## 退出与重新加入

退出前先确认手上的工作是否完成交接。项目负责人需要先转让负责人，再退出项目。

| 操作 | 本人的项目关系 | 对群聊、子区及分身的影响 |
| --- | --- | --- |
| 取消关注项目 | 保留 | 不退出群聊，不改变访问权限 |
| 退出一个项目普通群 | 保留 | 本人及分身离开这个群，并失去其全部子区访问权；其他群不因此退出 |
| 退出项目或被移出项目 | 结束 | 本人及分身离开全员群和项目普通群，失去相关子区及项目文件访问权 |
| 单独移除自己的分身 | 本人保留 | 只影响该分身在对应范围内的参与关系 |
| 重新加入项目 | 建立新的成员关系 | 自动进入全员群；原普通群、管理角色和分身关系不会自动恢复 |

::: warning 退出前确认影响范围
退出不会改写已经产生的消息、文件和历史作者关系，但会改变之后的访问与操作权限。不要把“历史仍保留”理解为退出后仍能查看项目内容。
:::
