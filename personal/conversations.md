# 描述需求与继续追问

与 Eva 对话时，把你希望得到的结果说清楚，再提供完成这件事需要的材料。你不需要一次写出很长的指令；先提出明确目标，再逐步补充即可。

## 描述需求

一个容易使用的顺序是：要做什么、依据什么、交给谁看、怎样呈现。下面的模板可以复制后替换：

```text
请根据【材料】完成【目标】，用于【读者或场景】。
结果请采用【格式】，包含【需要的内容】。
请遵守【限制】；缺少的信息标记为待确认。

材料：
【粘贴相关内容】
```

例如，“帮我写个总结”需要读者自行猜测范围。可以改成：

```text
请根据下面的供应链晨会记录，写一份给项目组看的简报。
分为“已确认事项、风险、下一步”三部分。
保留原始日期和数量；没有明确责任人的事项标为待确认。
不要代替项目组承诺交付时间。
```

发送前，在这段要求后补上实际会议记录。没有材料时，先请 Eva 帮你列出需要收集的信息。

## 补充材料

把事实和参考分开说明。例如：“下面是已确认报价”“下面是去年报告，仅参考结构”。如果材料较长，先指出你关注的部分，避免把无关内容全部放进来。

当前体验版首页的附件或模型控件可能不可用。可以先用非敏感的文字材料练习；文件没有出现在对话中时，不要按已提交文件继续操作。

## 修改要求

指出要改哪一部分、怎么改，以及哪些内容保留。比如：

```text
请只修改“下一步”部分，把每项写成“动作＋负责人＋时间”。
保留前两部分，不增加原文没有的数据。
负责人或时间没有确认的，继续标为待确认。
```

纠正事实时，要明确旧信息由什么替换，例如“刚才的批次号写错了，应为 A-2409，请按这个编号修改”。随后检查结果中是否还有旧值。

## 继续或新建对话

| 情况 | 做法 |
| --- | --- |
| 修改同一份材料的结构、语气或细节 | 继续当前对话 |
| 为当前问题补背景或纠正事实 | 继续当前对话，并说明更新内容 |
| 开始另一项无关工作 | 新建对话，使用清楚的名称 |
| 需要团队成员作出确认 | 将核对过的内容发到对应项目群 |

个人对话的内容需要由你选择后再带入团队讨论。下一步阅读[结果查看](./results.md)，或学习[整理历史对话](./organize.md)。
