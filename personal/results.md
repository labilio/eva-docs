# 结果查看

发出需求之后，先判断收到的是过程说明、确认消息，还是可以使用的结果。然后对照原材料检查内容，最后决定继续修改、保存或交给同事。

## 结果类型

| 内容 | 你可以怎样处理 |
| --- | --- |
| 已收到、正在处理等消息 | 查看后续进展，暂不当作完成结果 |
| 文字答复或整理表格 | 对照原始材料检查事实和遗漏 |
| 预览中的文档或演示文稿 | 检查结构、页面内容及具体数据 |
| 下载后的文件 | 在实际保存位置打开，确认格式和内容 |

当前原型的部分回复与产物是预置展示。它们用于理解界面，不能证明刚才输入的真实工作已经执行。

## 查看预置演示文稿

1. 打开「Eva 同学」。
2. 在历史列表找到「UI设计师发展前景的PPT」。分组收起时，先展开分组。
3. 打开对话，查看其中的任务过程和结果展示。
4. 对照演示内容，观察请求、过程与产物分别出现在哪里。

这份演示的主题和页面是预置的。它可以帮助你认识结果界面，不表示输入其他主题就会生成相应的真实 PPT。

## 核对内容

以[快速开始](../guide/quickstart.md)中的会议清单为例，可以逐项检查：

- 原文的每项工作是否都保留了，有没有漏掉质量部的事项。
- 负责人是否来自原文，有没有擅自填入姓名。
- 未确认的时间是否仍标为待确认。
- 输出格式是否方便接下来使用，例如复制到项目讨论中。

检查报告或表格时，也应关注数字、单位和统计范围。遇到没有来源的结论，要求说明依据或标出不确定之处。

## 修改结果

留在同一段对话，明确要调整的位置：

```text
第二项的截止时间尚未确认，请改为“待确认”。
其他内容保持不变，再把待确认事项单独列在末尾。
```

重新查看修改后的内容，确认旧信息已经替换，其他部分没有被误改。

## 保存与分享

界面提供下载操作时，执行后检查实际文件；仅看见预览不表示文件已下载。需要发送给团队时，先核对接收群和内容，再执行发送。

文字结果可以先复制保存。当前体验版的任务与附件不应作为可靠备份，数据范围见[适用范围](../help/scope.md)。团队资料的组织方式见[文件库](../resources/files.md)。
